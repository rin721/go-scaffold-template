# 产品需求：默认配置契约与可选 CLI 能力

## 背景与问题

当前 Kernel 可以显式组合 Database 等底层能力，并从文件、环境变量或内存来源加载配置，但项目使用方仍需手工拼写完整配置文件。能力已经拥有默认值和配置路径，却没有统一契约把这些信息交给配置管理，也没有一个可选的初始化命令生成当前项目实际组合出的配置骨架。

本需求要让每个底层能力拥有自己的默认配置策略，由配置管理显式聚合所有成功注入的能力，并通过启动前 CLI 生成一个完整、可审阅的项目配置文件。

## 目标用户与场景

- 项目初始化人员希望执行一条命令，得到当前项目实际启用能力的完整配置骨架。
- 能力维护者希望在能力包内维护字段、默认值、必填空值和敏感值策略，不让 Kernel 猜测这些业务规则。
- 应用装配者希望按项目需要启用或禁用 CLI，同时保持 Kernel 的显式注入方式不变。
- 自动化脚本希望选择 YAML 或 JSON、指定输出路径，并明确控制是否覆盖已有文件。

## 功能需求

### 默认配置契约

- 每个成功注入的 Kernel Definition 必须绑定一个默认配置契约；缺少契约时登记失败。
- 契约只产出当前能力配置路径下的内容。Capability ID 和配置路径由成功登记的 Definition 提供，能力不能在契约结果中伪造归属。
- 能力自行决定字段顺序、字段集合、默认值、必填空值和敏感值表现形式。
- Kernel 不判断某个 engine、driver、DSN、地址或凭据是否合理，只检查契约是否满足通用结构和控制协议。
- 当前 Database 是首个实现对象。它沿用现有默认骨架：`engine`、`driver`、`dsn` 保持空值，连接池和 Ping 超时使用 Database 自己已有的默认值。

### 默认配置生成

- 配置管理必须提供可由代码显式调用的接口，一次处理当前 composition 中全部成功登记的能力。
- 顶层配置段按 composition 的显式登记顺序输出；每个配置段内部保持能力契约声明的字段顺序。
- 支持以下目标扩展名，大小写不敏感：
  - `.yaml`、`.yml`：YAML。
  - `.json`：JSON。
- YAML 使用两个空格缩进；JSON 使用两个空格缩进；两种格式都以一个换行结束并表达相同数据语义。
- duration 必须输出为可读字符串，例如 `30m0s`、`5s`，不得在 JSON 中退化为纳秒整数。
- 目标路径为空或扩展名不受支持时返回错误，不创建文件。
- 目标父目录不存在时自动创建；目录权限目标为 `0700`，配置文件权限目标为 `0600`。Windows 上权限以操作系统可表达的语义为准。
- 默认拒绝覆盖已有目标文件。只有调用方显式设置 Force 时才允许替换。
- Force 替换必须先在目标目录生成完整临时文件并完成同步，再进行同文件系统替换；失败时保留原目标并清理临时文件。

### Abort 与失败

- 能力可以返回 Continue 或 Abort 控制结果，决定继续聚合还是中止整次生成。
- Abort 必须中止后续能力调用，不编码、不创建目标文件，也不覆盖已有目标。
- Abort 返回可识别的类型错误，同时保留能力提供的原始原因链。
- Abort 未提供原因、未知控制值、契约返回错误、重复或重叠配置路径、重复字段和非法值类型都视为整次生成失败。
- 任意失败都不得写出部分配置文件；Kernel 和配置管理不得用默认值掩盖失败。

### 可选 CLI

- CLI 通过 composition options 显式启用；未启用时不构造 CLI App，返回的 CLI 能力为 nil。
- CLI 启用后必须注册 `config init` 命令：
  - `--output`、`-o`：输出路径，默认 `config.yaml`。
  - `--force`、`-f`：允许替换已有文件，默认 `false`。
  - 不接受位置参数。
- `config init` 调用配置管理接口，不接收 Kernel，也不自行遍历能力。
- 成功时向 stdout 输出一行 `created default configuration: <path>`。
- 失败时沿用现有 CLI 的 `CommandError` 和退出码语义，并保留底层错误链。
- `config init` 必须能在配置文件尚不存在且 Kernel 尚未启动时执行；生成成功后不会自动启动或重载 Kernel。

## 验收标准

- 只组合 Database 时，YAML 和 JSON 均包含且仅包含 Database 契约提供的顶层配置段，并保持约定顺序和字符串 duration。
- 代码调用配置管理接口与执行 `config init` 产生相同字节语义的文件。
- CLI 禁用时，现有服务可继续通过 `kernel.New -> composition.Compose -> kernel.NewHost -> Host.Run` 启动，不需要 CLI 配置。
- 目标存在且未设置 Force 时原文件保持逐字节不变；设置 Force 后完整替换。
- 任一能力返回 Abort 或错误时，目标不存在则仍不存在，目标已存在则保持逐字节不变。
- 重复注入、缺少默认配置契约、重复配置路径和重复 CLI 命令均明确失败，不返回可误用的部分 Capabilities。

## 非目标

- 不提供配置注释、交互式逐项填写、模板变量或环境变量插值。
- 不接入远程配置中心，不在生成后自动加载、验证连接、启动或重载 Kernel。
- 不支持同一 Capability ID 的多个命名实例；“全部实例”仅指当前成功显式组合的唯一 Definition。
- 不提供依赖运行中 Access 的 CLI 命令，不把 CLI 加入 Supervisor Task。
- 不增加自动发现、字段注入、全局注册表、Service Locator 或通用依赖 DAG。
