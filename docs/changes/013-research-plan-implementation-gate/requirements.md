# 产品需求：研究优先任务门禁

## 1. 背景与问题

003 已建立“计划文档 -> 用户确认 -> 实施”的强制门禁，但“事实分析”只出现在状态机开头，没有独立阶段、可检索产物、通过条件和证据时效要求。012 随后使用 `metadata.yaml + report.md` 建立了结构化研究档案，并证明先复用研究、再补证据、最后综合形成方案可以避免在底层契约未闭合时过早设计业务接口。

用户要求把 012 的研究学习模式提升为每次任务的门禁规则，固定顺序为先研究、再计划、最后实现代码。

## 2. 目标

- 所有仓库任务都先进入研究阶段，研究门禁通过后才允许形成计划。
- 每项新变更都有可检索、可复核的任务级研究档案，能够定位问题、证据快照、适用性、时效和替代关系。
- 计划明确引用研究结论，不把未经证实的假设写成需求、接口或文件修改。
- 非纯文档实现继续等待计划报告后的独立用户确认；初始实现请求不跨越门禁。
- 实施中出现推翻前提或实质改变范围的新证据时，能够回退到研究或计划阶段并重新确认。

## 3. 范围

### 3.1 包含

- 根 `AGENTS.md` 的任务状态机、研究阶段、计划阶段、确认与实施规则。
- `docs/research/README.md` 的通用检索方法、最小 metadata、报告内容、状态与替代语义。
- `docs/changes` 固定结构和导航说明。
- 013 自身的研究、需求、设计、任务和验证记录。

### 3.2 不包含

- Go 源码、配置、依赖、脚本、测试或运行行为变更。
- 强制每个任务联网，或为了形式完整而泛泛罗列框架。
- 把历史 001-012 全量补造成新格式；历史记录保持原貌，后续任务从 013 开始执行新门禁。
- 用研究档案代替权威主题文档、用户确认、实现验证或 ADR。

## 4. 约束

- 研究必须从当前仓库事实出发，文档只能作为待代码验证的声明。
- 既有研究先检索、再复用或复核；易漂移事实不能仅凭旧摘要进入当前计划。
- 外部证据优先官方源码、官方文档、标准、官方示例和测试。
- 研究记录必须区分事实、推断、用户决策、目标设计和当前实现。
- 纯文档任务可以直接完成，但也必须保持“研究 -> 计划 -> 文档实施”的顺序。
- 003 和 012 作为历史证据不重写；当前流程由根 `AGENTS.md` 和 `docs/research/README.md` 统一说明。

## 5. 验收标准

- `AGENTS.md` 明确定义“研究中 -> 研究门禁通过 -> 计划中”，并分别进入纯文档直接实施或非纯文档“待确认 -> 已确认 -> 实施”的分支。
- 研究门禁具有输入、检索、证据、档案、通过条件和回退条件，不只是原则性口号。
- 每个新变更目录固定包含 `research/`，每个任务至少有一份 `metadata.yaml + report.md` 研究记录。
- 计划必须引用研究 ID；非纯文档实现仍要求独立后续确认。
- 只读分析、纯文档交付、一般实现和实质变更分别具有明确处理方式。
- 013 文档与导航链接有效，`git diff --check` 通过，提交不混入既有 `.agents/skills` 迁移或 `tmp/` 内容。
