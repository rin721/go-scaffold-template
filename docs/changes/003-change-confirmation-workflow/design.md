# 开发设计：变更确认流程

## 1. 文档结构

根 `README.md` 增加 `docs/README.md` 入口；`docs/README.md` 路由当前主题与 `docs/changes/README.md`。任务级记录继续使用稳定序号，但从旧根目录单轨迁入 `docs/changes`。

每个任务目录固定包含：

- `README.md`：状态、范围和阅读入口。
- `requirements.md`：目标、范围、约束、非目标与验收。
- `design.md`：实现方案、接口、文件影响、失败语义与验证。
- `tasks.md`：稳定任务 ID、工作量、依赖、确认状态、证据、Commit 和风险。

## 2. 确认状态机

```text
事实分析
  -> 建立任务文档（待确认）
  -> 提交需求报告并停止
  -> 用户在后续消息明确确认
  -> 已确认
  -> 按任务 ID 实施与验证
  -> 同步权威文档和任务证据
  -> 提交
```

- 方案阶段只改变当前任务文档和必要导航，不暂存、不提交、不修改实现、不执行状态变更命令。
- 初始请求不能跨越“待确认”；其他任务或历史消息中的确认不能复用。
- 目标、公共接口、依赖、边界、迁移或外部副作用实质变化时回到“待确认”。
- 纯文档最终交付和无副作用只读分析不要求额外确认。

- 执行 `git diff --check`，审阅工作树与暂存 Diff。
- 只精确暂存 `AGENTS.md`、根 README 和 `docs/**` 的本任务内容。
- 创建 `docs: 重构变更确认流程与文档目录`，不 push。
- 本任务无 Go 变更，因此不运行 build、test、race 或 vet。
